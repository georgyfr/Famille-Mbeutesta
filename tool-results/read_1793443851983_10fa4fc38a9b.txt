    34→### SYNTHÈSE GLOBALE (mémo détaillé)
    35→
    36→**Vision/problématique** : FamilleConnect = 1ère plateforme de gouvernance des grandes familles africaines (100–500 membres, Cameroun/CEMAC). Problème : WhatsApp + cahiers + appels ne gèrent rien (pas de registre fiable, cotisations oubliées, décisions contestées, mémoire qui disparaît avec les anciens). Proposition : « système d'exploitation numérique de la famille » en 7 univers. Respect de l'hybridité tradition/démocratie, polygamie, adoption traditionnelle, conjoints externes, diaspora, langues locales, Mobile Money natif.
    37→
    38→**Cible/marché** : familles structurées (patriarche/conseil, chefs de branche, réunions mensuelles/trimestrielles, congrès, cotisations, caisse familiale). Marché : Cameroun 3 000–5 000 familles (600k–1M membres, 60–100 M FCFA/an) ; CEMAC 10 000–15 000 familles (2–3 M membres, 200–300 M FCFA/an) ; Afrique francophone 50 000+ familles (1–2 milliards FCFA/an) ; diaspora 10 M+ (complément). Hypothèses pénétration 5–15 % sur 5 ans. Extension possible : associations villageoises, tontines, congrégations (x5–x10).
    39→
    40→**Les 7 univers** (rôle | modules | KPI phare) :
    41→- U1 Famille (socle, priorité 1) : registre fiche membre 9 blocs, arbre généalogique interactif, hiérarchie 5 niveaux de rôles (patriarche → junior), cartographie diaspora. Différenciateur : cas africains (polygamie, brouille, décédés). KPI ≥ 90 % complétude registre an 1.
    42→- U2 Vie familiale : 23 types d'événements (3 familles : heureux/malheureux/institutionnels), moteur workflow automatisé (décès 8 étapes, mariage 9, congrès 10), calendrier multi-fuseaux + sync Google/Apple/Outlook, inscriptions/logistique. KPI ≤ 30 min annonce décès.
    43→- U3 Solidarité (le plus sensible) : dossier auto-déclenché depuis U2 (7 sections, 5 états), collecte multi-canaux multi-devises, barème gradué, exonérations confidentielles (dignité), journal immutable, double validation > 50 000 FCFA, justificatifs > 10 000 FCFA. KPI ≤ 4 h déclenchement collecte.
    44→- U4 Finances (poumon technique, priorité MVP) : 6 types de caisses, Mobile Money natif (MTN MoMo + Orange Money, webhooks, rapprochement auto, mode hors-ligne), comptabilité SYSCOHADA partie double, audit triple seuils 10k/50k/500k FCFA. KPI ≥ 80 % cotisation à jour.
    45→- U5 Gouvernance : 5 niveaux de décision (consultation, vote simple, vote responsables, vote conseil, décision patriarche), 10 types de comités, élections 5 étapes (bulletins chiffrés, 2FA), règlement intérieur versionné (amendement 2/3). KPI ≥ 60 % participation.
    46→- U6 Mémoire : archivage automatique des dossiers clôturés U2–U5, mémoire des anciens (interviews audio/vidéo + transcription, urgence : 50 % an 1, 90 % à 3 ans), patrimoine immatériel 7 types (coutumes, recettes, chansons, proverbes, lieux, langues, savoir-faire), conservation triple stockage + formats durables + migration 5 ans. KPI 100 % archivage auto.
    47→- U7 Réseau (transversal) : compétences 12 catégories (vérifiées par chef de branche), mentorat 5 types, diaspora (relais par pays, accueil 30 j), opportunités 8 types (modération a priori ; distinction entraide bénévole vs mission rémunérée ; anti-harcèlement : blocage, plafond, tolérance zéro). KPI ≥ 60 % profils compétences adultes.
    48→- Flux inter-univers : U2→U3 (création dossier), U3→U4 (écritures/paiements MM), U4↔U5 (budget/décisions), U2-U3-U4-U5→U6 (archivage auto), U1→U7 (membres/diaspora), U6→U7 (biographies mentorat). Effet réseau = lock-in.
    49→
    50→**MVP (Phase 1, 9 mois)** : U1 registre+branches+rôles minimaux+dashboard ; U4 caisse principale, cotisations trimestrielles, Mobile Money MTN+Orange, journal comptable immutable, double validation, reçus PDF ; U2 8 types essentiels, calendrier, dossier simple, workflow statique décès ; commun : Android + web responsive + 2FA. Critères de sortie : ≥ 90 % complétude, ≥ 80 % cotisation à jour, ≥ 95 % rapprochement MM, 5 familles pilotes onboardées. Phase 2 (mois 10–18) : arbre interactif+diaspora, catalogue 23 types + workflows configurables, U3 complet, caisse multi-niveaux + SYSCOHADA + audit, votes simples+comités+PV+règlement (sortie : 30 familles, ≥ 60 % participation, clôture ≤ 90 j). Phase 3 (mois 19–30) : élections formelles, U6 complet, U7 complet, IA langage naturel, hors-ligne robuste, notifs vocales, multi-famille (sortie : 100 familles, ≥ 50 % anciens interviewés, IA opérationnelle).
    51→
    52→**Modèle économique** : freemium 0 FCFA < 50 membres ; abonnement familial 10 000 FCFA/an (50–200 membres) ; 25 000 FCFA/an (200+) — prélevé sur la caisse familiale ; onboarding 100k–500k FCFA ; audit 200k–1M FCFA/an. Équilibre ≈ 500 familles abonnées (18–24 mois post-lancement) ; rentabilité an 4 (2 000+ familles). ARR : 1 000 familles ≈ 15 M FCFA ; 5 000 ≈ 75 M.
    53→
    54→**Budget/équipe** : P1 : 2 devs + 1 designer + 1 PM + 1 référent = 40–60 M FCFA ; P2 : 60–90 M ; P3 : 100–150 M ; total 30 mois ≈ 200–300 M FCFA, équipe jusqu'à 15. Levée recherchée : 100–200 M FCFA sur 24 mois (equity). Fonds : 55 % salaires tech, 15 % infra/licences, 15 % accompagnement pilotes, 10 % marketing, 5 % réserve.
    55→
    56→**Risques top 8** (probabilité/impact → mitigation) : adoption aînés (élevée/critique → gros caractères, notifs vocales, référent humain) ; fraude financière (faible/critique → journal immutable, double validation, audit aléatoire) ; dépendance Mobile Money (moyenne/élevé → double intégration MTN+Orange, mode espèces) ; conflits aggravés par transparence (→ comité médiation, recours, confidentialité) ; concurrence WhatsApp/Meta (élevée/moyen → spécialisation, lock-in mémoire) ; coûts infra sous-estimés ; réglementaire RGPD/OHADA (→ conformité by design, hébergement local envisageable) ; recrutement Cameroun (→ formation interne, télétravail diaspora).
    57→
    58→**KPI** : an 1 — 5–10 familles pilotes, 1 500–3 000 membres, ≥ 90 % complétude, ≥ 80 % cotisation, ≤ 30 min annonce, ≤ 4 h collecte, ≥ 4/5 satisfaction. An 3 — 100+ familles, 30 000+ membres, ARR 100–200 M FCFA, rétention ≥ 90 %, ≥ 500 interviews anciens, ≥ 200 mentorats. Go-to-market : pilotes (gratuité totale contre témoignages), ambassadeurs, partenariats institutionnels (MTN, Orange, Afriland/BICEC/SGBC, ministère Culture, églises, diaspora). Partenariats : distribution, technologique, institutionnel, capital. 46 000 mots de specs (~6 000/univers). Prochaines étapes : validation spec, 35 maquettes (5/univers), choix stack, recrutement P1, onboarding pilotes, MVP en prod à 9 mois.

    60→### ARCHITECTURE TECHNIQUE (mémo détaillé)
    61→
    62→**5 principes directeurs** : offline-first (connectivité intermittente zones rurales), security by design (données santé/précarité/finances), scalabilité maîtrisée (5 familles → plusieurs milliers), coût optimisé (cible < 500 FCFA/membre/mois), interopérabilité native (MM, calendriers, multi-appareils). Latence cible : < 500 ms (95 % REST), < 2 s (95 % WebSocket).
    63→
    64→**Stack récapitulative (table section 12)** : Mobile = React Native + TypeScript (alt. Flutter écartée) ; Web = Next.js 16 + TypeScript + Tailwind (App Router, SSR/SSG, Server Components, Streaming/Suspense, PWA service worker/cache API/background sync ; alt. Remix, Nuxt) ; Back-end = NestJS + TypeScript « microservices modérés » (monolithe modulaire, alt. Express/Fastify) ; API REST = NestJS + Swagger (OpenAPI 3.0, `/api/v1/`, pagination curseur, erreurs standardisées) ; GraphQL = Apollo Server schema-first + DataLoader anti N+1 + persisted queries (arbre généalogique, dashboards, recherche) ; WebSocket = Socket.io (reconnexion auto, buffer 5 min, rooms : messagerie U7, votes U5, suivi collecte U3) ; DB = PostgreSQL 15+ ; Cache = Redis 7+ (cache TTL, sessions JWT révocables, rate limiting, file BullMQ, locks distribués, WebSocket adapter) ; Recherche = Elasticsearch 8+/OpenSearch (full-text U6/U7/U1, alimenté via CDC depuis PostgreSQL) ; Stockage = S3 (P1) / MinIO (P2-P3) ; ORM = Prisma ; Files = Redis BullMQ ; Conteneurs = Docker ; Orchestration = AWS ECS + Fargate (K8s/EKS optionnel P3) ; Cloud = AWS (alt. Azure, Hetzner) ; CDN = Cloudflare ou CloudFront ; DNS = Route 53 (alt. Cloudflare DNS) ; Monitoring = Datadog + CloudWatch ; CI/CD = GitHub Actions (lint→tests Jest >80 %→build→tests intégration→staging→e2e Playwright→prod manuelle ; k6 charge ; blue-green ; feature flags ; rollback < 5 min) ; Secrets = AWS Secrets Manager (rotation 90 j) ; Tests = Jest + Playwright.
    65→
    66→**Modules back-end** : 7 modules métiers U1–U7 + transverses : Auth Service (JWT 1 h access / 30 j refresh révocables, 2FA, RBAC 5 rôles, OAuth Google/Apple), Notification Engine (catalogue 121 notifications, priorités Critique→Silencieux, ciblage branche/génération/diaspora/rôle, fuseaux + heures de repos 22h-7h, anti-saturation plafonds/digests, multi-canal push/SMS/vocal/email), Workflow Engine (définitions YAML/JSON configurables sans code, instances, étapes, retards J+N + relances, audit), Audit Service (journal immuable), File Storage Service, Search Service.
    67→
    68→**Mobile offline-first** : SQLite locale chiffrée (SQLCipher AES-256), moteur de synchronisation (conflits : dernière modification gagne ou résolution manuelle), file d'attente persistante d'actions (« En attente de synchronisation » → « Synchronisé »), cache agressif. Push FCM/APNs + silencieuses. Biométrie Face ID/Touch ID. Distribution : Google Play + APK direct (Cameroun), CodePush pour updates JS. Semver N-2. Accessibilité : gros caractères, max 3 taps, notifs vocales, i18n fr/en + langues locales (medumba, fe'fe', ghomala', ewondo, duala), mode sombre.
    69→
    70→**Sécurité** : bcrypt coût 12 ; 2FA OTP SMS obligatoire (paiement > 50 000 FCFA, vote, modification rôles ; validité 5 min) ; RBAC (5 rôles) + ABAC (branche, génération, localisation) ; moindre privilège ; audit des accès sensibles ; TLS 1.3 en transit ; AES-256 au repos (PostgreSQL, S3, Redis) ; SQLCipher mobile ; AWS KMS ; RGPD-like (accès, rectification, effacement partiel sous réserve U6, portabilité JSON, consentement explicite, journal des consultations) ; Secrets Manager (jamais de secrets dans le code) ; webhooks signés HMAC SHA-256 idempotents ; rate limiting 100 req/min authentifié / 10 anonyme ; CORS strict ; Helmet ; class-validator + sanitization.
    71→
    72→**Base de données** : PostgreSQL (ACID pour finances, immutabilité via tables d'audit + triggers, soft delete `deleted_at`, écritures compensatoires jamais d'UPDATE, réplica en lecture, WAL point-in-time) ; organisation en 8 schemas PostgreSQL (voir schéma ci-dessous) ; partitionnement mensuel/annuel des tables volumineuses. Sauvegardes : PostgreSQL quotidienne + WAL (30 j en ligne, 1 an archive froide), Redis snapshot 6 h (7 j), ES quotidien, S3 cross-region + versioning + lifecycle 90 j, export externe trimestriel chiffré, test de restauration annuel.
    73→
    74→**Stockage fichiers** : buckets par univers — `s3://familleconnect/u1-membres/{photos-profil,documents-identite}`, `u2-evenements/{albums,programmes}`, `u3-solidarite/justificatifs`, `u4-finances/{justificatifs-depenses,releves}`, `u5-gouvernance/{pv,reglement}`, `u6-memoire/{interviews-audio,interviews-video,documents-historiques,traditions}`, `u7-reseau/portfolios`. URLs signées à durée limitée. Triple stockage pour U6 (S3 + sauvegarde externalisée + archive froide Glacier).

    78→**Intégrations externes** : MTN MoMo Open API (REST, OAuth 2.0, collection, webhook statut, rapprochement auto, sandbox) ; Orange Money Web Payment (clé API, webhook) ; Google Calendar (bidirectionnel OAuth 2.0), Apple Calendar (iCal read-only), Outlook (Microsoft Graph bidirectionnel), iCal générique ; SMS = Twilio ou Africa's Talking / Cammob (5–15 FCFA/SMS ; décès, 2FA, relances) ; e-mail = Amazon SES/SendGrid (rapports, bilans, diaspora) ; push = FCM (Android) + APNs (iOS) + Web Push ; visio P2 = Zoom / Google Meet / Jitsi Meet (auto-hébergeable).

    84→### SCHÉMA POSTGRESQL (mémo détaillé) — à transposer vers D1/SQLite + KV + R2
    85→
    86→**Organisation** : 8 schemas = `commun` (transverse), `famille` (U1), `vie_familiale` (U2), `solidarite` (U3), `finances` (U4), `gouvernance` (U5), `memoire` (U6), `reseau` (U7). Champs communs à toutes les tables : `id UUID PK DEFAULT gen_random_uuid()`, `created_at/by`, `updated_at/by`, `deleted_at/by` (soft delete, jamais de DELETE physique), `version INTEGER` (optimistic locking). Types : TIMESTAMPTZ (UTC uniquement, conversion à l'affichage), DATE, TIME, VARCHAR(n), TEXT, JSONB, NUMERIC(15,2) pour tous les montants, BOOLEAN, ENUM, INET (IP audit), BYTEA (rare, signatures), BIGSERIAL (numéros séquentiels). Conventions : snake_case, tables au singulier, suffixes `_id/_at/_date/_count/_status`, tables d'audit préfixées `audit_`.
