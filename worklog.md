### SYNTHÈSE GLOBALE (mémo détaillé)

**Vision/problématique** : FamilleConnect = 1ère plateforme de gouvernance des grandes familles africaines (100–500 membres, Cameroun/CEMAC). Problème : WhatsApp + cahiers + appels ne gèrent rien (pas de registre fiable, cotisations oubliées, décisions contestées, mémoire qui disparaît avec les anciens). Proposition : « système d'exploitation numérique de la famille » en 7 univers. Respect de l'hybridité tradition/démocratie, polygamie, adoption traditionnelle, conjoints externes, diaspora, langues locales, Mobile Money natif.

**Cible/marché** : familles structurées (patriarche/conseil, chefs de branche, réunions mensuelles/trimestrielles, congrès, cotisations, caisse familiale). Marché : Cameroun 3 000–5 000 familles (600k–1M membres, 60–100 M FCFA/an) ; CEMAC 10 000–15 000 familles (2–3 M membres, 200–300 M FCFA/an) ; Afrique francophone 50 000+ familles (1–2 milliards FCFA/an) ; diaspora 10 M+ (complément). Hypothèses pénétration 5–15 % sur 5 ans. Extension possible : associations villageoises, tontines, congrégations (x5–x10).

**Les 7 univers** (rôle | modules | KPI phare) :
- U1 Famille (socle, priorité 1) : registre fiche membre 9 blocs, arbre généalogique interactif, hiérarchie 5 niveaux de rôles (patriarche → junior), cartographie diaspora. Différenciateur : cas africains (polygamie, brouille, décédés). KPI ≥ 90 % complétude registre an 1.
- U2 Vie familiale : 23 types d'événements (3 familles : heureux/malheureux/institutionnels), moteur workflow automatisé (décès 8 étapes, mariage 9, congrès 10), calendrier multi-fuseaux + sync Google/Apple/Outlook, inscriptions/logistique. KPI ≤ 30 min annonce décès.
- U3 Solidarité (le plus sensible) : dossier auto-déclenché depuis U2 (7 sections, 5 états), collecte multi-canaux multi-devises, barème gradué, exonérations confidentielles (dignité), journal immutable, double validation > 50 000 FCFA, justificatifs > 10 000 FCFA. KPI ≤ 4 h déclenchement collecte.
- U4 Finances (poumon technique, priorité MVP) : 6 types de caisses, Mobile Money natif (MTN MoMo + Orange Money, webhooks, rapprochement auto, mode hors-ligne), comptabilité SYSCOHADA partie double, audit triple seuils 10k/50k/500k FCFA. KPI ≥ 80 % cotisation à jour.
- U5 Gouvernance : 5 niveaux de décision (consultation, vote simple, vote responsables, vote conseil, décision patriarche), 10 types de comités, élections 5 étapes (bulletins chiffrés, 2FA), règlement intérieur versionné (amendement 2/3). KPI ≥ 60 % participation.
- U6 Mémoire : archivage automatique des dossiers clôturés U2–U5, mémoire des anciens (interviews audio/vidéo + transcription, urgence : 50 % an 1, 90 % à 3 ans), patrimoine immatériel 7 types (coutumes, recettes, chansons, proverbes, lieux, langues, savoir-faire), conservation triple stockage + formats durables + migration 5 ans. KPI 100 % archivage auto.
- U7 Réseau (transversal) : compétences 12 catégories (vérifiées par chef de branche), mentorat 5 types, diaspora (relais par pays, accueil 30 j), opportunités 8 types (modération a priori ; distinction entraide bénévole vs mission rémunérée ; anti-harcèlement : blocage, plafond, tolérance zéro). KPI ≥ 60 % profils compétences adultes.
- Flux inter-univers : U2→U3 (création dossier), U3→U4 (écritures/paiements MM), U4↔U5 (budget/décisions), U2-U3-U4-U5→U6 (archivage auto), U1→U7 (membres/diaspora), U6→U7 (biographies mentorat). Effet réseau = lock-in.

**MVP (Phase 1, 9 mois)** : U1 registre+branches+rôles minimaux+dashboard ; U4 caisse principale, cotisations trimestrielles, Mobile Money MTN+Orange, journal comptable immutable, double validation, reçus PDF ; U2 8 types essentiels, calendrier, dossier simple, workflow statique décès ; commun : Android + web responsive + 2FA. Critères de sortie : ≥ 90 % complétude, ≥ 80 % cotisation à jour, ≥ 95 % rapprochement MM, 5 familles pilotes onboardées. Phase 2 (mois 10–18) : arbre interactif+diaspora, catalogue 23 types + workflows configurables, U3 complet, caisse multi-niveaux + SYSCOHADA + audit, votes simples+comités+PV+règlement (sortie : 30 familles, ≥ 60 % participation, clôture ≤ 90 j). Phase 3 (mois 19–30) : élections formelles, U6 complet, U7 complet, IA langage naturel, hors-ligne robuste, notifs vocales, multi-famille (sortie : 100 familles, ≥ 50 % anciens interviewés, IA opérationnelle).

**Modèle économique** : freemium 0 FCFA < 50 membres ; abonnement familial 10 000 FCFA/an (50–200 membres) ; 25 000 FCFA/an (200+) — prélevé sur la caisse familiale ; onboarding 100k–500k FCFA ; audit 200k–1M FCFA/an. Équilibre ≈ 500 familles abonnées (18–24 mois post-lancement) ; rentabilité an 4 (2 000+ familles). ARR : 1 000 familles ≈ 15 M FCFA ; 5 000 ≈ 75 M.

**Budget/équipe** : P1 : 2 devs + 1 designer + 1 PM + 1 référent = 40–60 M FCFA ; P2 : 60–90 M ; P3 : 100–150 M ; total 30 mois ≈ 200–300 M FCFA, équipe jusqu'à 15. Levée recherchée : 100–200 M FCFA sur 24 mois (equity). Fonds : 55 % salaires tech, 15 % infra/licences, 15 % accompagnement pilotes, 10 % marketing, 5 % réserve.

**Risques top 8** (probabilité/impact → mitigation) : adoption aînés (élevée/critique → gros caractères, notifs vocales, référent humain) ; fraude financière (faible/critique → journal immutable, double validation, audit aléatoire) ; dépendance Mobile Money (moyenne/élevé → double intégration MTN+Orange, mode espèces) ; conflits aggravés par transparence (→ comité médiation, recours, confidentialité) ; concurrence WhatsApp/Meta (élevée/moyen → spécialisation, lock-in mémoire) ; coûts infra sous-estimés ; réglementaire RGPD/OHADA (→ conformité by design, hébergement local envisageable) ; recrutement Cameroun (→ formation interne, télétravail diaspora).

**KPI** : an 1 — 5–10 familles pilotes, 1 500–3 000 membres, ≥ 90 % complétude, ≥ 80 % cotisation, ≤ 30 min annonce, ≤ 4 h collecte, ≥ 4/5 satisfaction. An 3 — 100+ familles, 30 000+ membres, ARR 100–200 M FCFA, rétention ≥ 90 %, ≥ 500 interviews anciens, ≥ 200 mentorats. Go-to-market : pilotes (gratuité totale contre témoignages), ambassadeurs, partenariats institutionnels (MTN, Orange, Afriland/BICEC/SGBC, ministère Culture, églises, diaspora). Partenariats : distribution, technologique, institutionnel, capital. 46 000 mots de specs (~6 000/univers). Prochaines étapes : validation spec, 35 maquettes (5/univers), choix stack, recrutement P1, onboarding pilotes, MVP en prod à 9 mois.

### ARCHITECTURE TECHNIQUE (mémo détaillé)

**5 principes directeurs** : offline-first (connectivité intermittente zones rurales), security by design (données santé/précarité/finances), scalabilité maîtrisée (5 familles → plusieurs milliers), coût optimisé (cible < 500 FCFA/membre/mois), interopérabilité native (MM, calendriers, multi-appareils). Latence cible : < 500 ms (95 % REST), < 2 s (95 % WebSocket).

**Stack récapitulative (table section 12)** : Mobile = React Native + TypeScript (alt. Flutter écartée) ; Web = Next.js 16 + TypeScript + Tailwind (App Router, SSR/SSG, Server Components, Streaming/Suspense, PWA service worker/cache API/background sync ; alt. Remix, Nuxt) ; Back-end = NestJS + TypeScript « microservices modérés » (monolithe modulaire, alt. Express/Fastify) ; API REST = NestJS + Swagger (OpenAPI 3.0, `/api/v1/`, pagination curseur, erreurs standardisées) ; GraphQL = Apollo Server schema-first + DataLoader anti N+1 + persisted queries (arbre généalogique, dashboards, recherche) ; WebSocket = Socket.io (reconnexion auto, buffer 5 min, rooms : messagerie U7, votes U5, suivi collecte U3) ; DB = PostgreSQL 15+ ; Cache = Redis 7+ (cache TTL, sessions JWT révocables, rate limiting, file BullMQ, locks distribués, WebSocket adapter) ; Recherche = Elasticsearch 8+/OpenSearch (full-text U6/U7/U1, alimenté via CDC depuis PostgreSQL) ; Stockage = S3 (P1) / MinIO (P2-P3) ; ORM = Prisma ; Files = Redis BullMQ ; Conteneurs = Docker ; Orchestration = AWS ECS + Fargate (K8s/EKS optionnel P3) ; Cloud = AWS (alt. Azure, Hetzner) ; CDN = Cloudflare ou CloudFront ; DNS = Route 53 (alt. Cloudflare DNS) ; Monitoring = Datadog + CloudWatch ; CI/CD = GitHub Actions (lint→tests Jest >80 %→build→tests intégration→staging→e2e Playwright→prod manuelle ; k6 charge ; blue-green ; feature flags ; rollback < 5 min) ; Secrets = AWS Secrets Manager (rotation 90 j) ; Tests = Jest + Playwright.

**Modules back-end** : 7 modules métiers U1–U7 + transverses : Auth Service (JWT 1 h access / 30 j refresh révocables, 2FA, RBAC 5 rôles, OAuth Google/Apple), Notification Engine (catalogue 121 notifications, priorités Critique→Silencieux, ciblage branche/génération/diaspora/rôle, fuseaux + heures de repos 22h-7h, anti-saturation plafonds/digests, multi-canal push/SMS/vocal/email), Workflow Engine (définitions YAML/JSON configurables sans code, instances, étapes, retards J+N + relances, audit), Audit Service (journal immuable), File Storage Service, Search Service.

**Mobile offline-first** : SQLite locale chiffrée (SQLCipher AES-256), moteur de synchronisation (conflits : dernière modification gagne ou résolution manuelle), file d'attente persistante d'actions (« En attente de synchronisation » → « Synchronisé »), cache agressif. Push FCM/APNs + silencieuses. Biométrie Face ID/Touch ID. Distribution : Google Play + APK direct (Cameroun), CodePush pour updates JS. Semver N-2. Accessibilité : gros caractères, max 3 taps, notifs vocales, i18n fr/en + langues locales (medumba, fe'fe', ghomala', ewondo, duala), mode sombre.

**Sécurité** : bcrypt coût 12 ; 2FA OTP SMS obligatoire (paiement > 50 000 FCFA, vote, modification rôles ; validité 5 min) ; RBAC (5 rôles) + ABAC (branche, génération, localisation) ; moindre privilège ; audit des accès sensibles ; TLS 1.3 en transit ; AES-256 au repos (PostgreSQL, S3, Redis) ; SQLCipher mobile ; AWS KMS ; RGPD-like (accès, rectification, effacement partiel sous réserve U6, portabilité JSON, consentement explicite, journal des consultations) ; Secrets Manager (jamais de secrets dans le code) ; webhooks signés HMAC SHA-256 idempotents ; rate limiting 100 req/min authentifié / 10 anonyme ; CORS strict ; Helmet ; class-validator + sanitization.

**Base de données** : PostgreSQL (ACID pour finances, immutabilité via tables d'audit + triggers, soft delete `deleted_at`, écritures compensatoires jamais d'UPDATE, réplica en lecture, WAL point-in-time) ; organisation en 8 schemas PostgreSQL (voir schéma ci-dessous) ; partitionnement mensuel/annuel des tables volumineuses. Sauvegardes : PostgreSQL quotidienne + WAL (30 j en ligne, 1 an archive froide), Redis snapshot 6 h (7 j), ES quotidien, S3 cross-region + versioning + lifecycle 90 j, export externe trimestriel chiffré, test de restauration annuel.

**Stockage fichiers** : buckets par univers — `s3://familleconnect/u1-membres/{photos-profil,documents-identite}`, `u2-evenements/{albums,programmes}`, `u3-solidarite/justificatifs`, `u4-finances/{justificatifs-depenses,releves}`, `u5-gouvernance/{pv,reglement}`, `u6-memoire/{interviews-audio,interviews-video,documents-historiques,traditions}`, `u7-reseau/portfolios`. URLs signées à durée limitée. Triple stockage pour U6 (S3 + sauvegarde externalisée + archive froide Glacier).

**Hébergement (à transposer vers Cloudflare)** : recommandation d'origine = AWS af-south-1 (Afrique du Sud, zone principale) + eu-west-3/eu-central-1 (diaspora, redondance) ; ALB, ECS Fargate, RDS PostgreSQL multi-AZ, ElastiCache, OpenSearch, S3+Glacier, Route 53, CloudWatch+Datadog ; multi-AZ, multi-région P3 ; RTO 4 h / RPO 1 h ; Hetzner comme alternative coût ; CDN Cloudflare déjà cité en option ; hébergement local Cameroun/CEMAC envisagé P3 (Camtel, MTN Business) pour souveraineté. **Pivots de migration Cloudflare** : remplacer ECS/ALB par Workers/Pages ; RDS→D1 (transposer les 60 tables, cf. notes ci-dessous) ; Redis→KV/DO ; S3→R2 (mêmes buckets, URLs signées natives) ; OpenSearch→recherche D1/Vectorize ; ElastiCache→KV ; Secrets Manager→Workers Secrets/KV ; Datadog→Workers Analytics/observabilité ; workflows→Workflows/Queues/Cron Triggers ; WebSocket→Durable Objects.

**Intégrations externes** : MTN MoMo Open API (REST, OAuth 2.0, collection, webhook statut, rapprochement auto, sandbox) ; Orange Money Web Payment (clé API, webhook) ; Google Calendar (bidirectionnel OAuth 2.0), Apple Calendar (iCal read-only), Outlook (Microsoft Graph bidirectionnel), iCal générique ; SMS = Twilio ou Africa's Talking / Cammob (5–15 FCFA/SMS ; décès, 2FA, relances) ; e-mail = Amazon SES/SendGrid (rapports, bilans, diaspora) ; push = FCM (Android) + APNs (iOS) + Web Push ; visio P2 = Zoom / Google Meet / Jitsi Meet (auto-hébergeable).

**Performance/scalabilité** : caches en 4 niveaux (Redis, HTTP ETag, CDN, SQLite mobile) avec invalidation par entité ; index partiels/composites ; partitionnement écritures comptables + notifications ; EXPLAIN ANALYZE ; DataLoader + eager loading (anti N+1) ; pagination curseur (jamais OFFSET) ; back-end stateless + auto-scaling CPU/mémoire ; read replicas ; workers asynchrones. Pics gérés : décès simultanés (10× trafic notifs), congrès (centaines de connexions), clôture de votes, jours de paie Mobile Money.

**Coûts infra d'origine** : P1 855k–1,475 M FCFA/mois (1–3k membres), P2 2,5–5,5 M (9–30k), P3 12–42 M (150–600k) ; coût/membre/mois 350–1 000 → 180–600 → 70–280 FCFA. La migration Cloudflare doit viser mieux que la cible < 500 FCFA/membre/mois.

### SCHÉMA POSTGRESQL (mémo détaillé) — à transposer vers D1/SQLite + KV + R2

**Organisation** : 8 schemas = `commun` (transverse), `famille` (U1), `vie_familiale` (U2), `solidarite` (U3), `finances` (U4), `gouvernance` (U5), `memoire` (U6), `reseau` (U7). Champs communs à toutes les tables : `id UUID PK DEFAULT gen_random_uuid()`, `created_at/by`, `updated_at/by`, `deleted_at/by` (soft delete, jamais de DELETE physique), `version INTEGER` (optimistic locking). Types : TIMESTAMPTZ (UTC uniquement, conversion à l'affichage), DATE, TIME, VARCHAR(n), TEXT, JSONB, NUMERIC(15,2) pour tous les montants, BOOLEAN, ENUM, INET (IP audit), BYTEA (rare, signatures), BIGSERIAL (numéros séquentiels). Conventions : snake_case, tables au singulier, suffixes `_id/_at/_date/_count/_status`, tables d'audit préfixées `audit_`.

**Liste complète des tables (60 dans le DDL ; le doc annonce 52)** :

*Schéma commun (8)* :
1. `commun.user` — email UNIQUE VARCHAR(255), phone UNIQUE VARCHAR(20), password_hash, failed_login_count, locked_until, last_login_at, last_login_ip INET, two_factor_enabled, two_factor_phone, locale ('fr'), timezone ('Africa/Douala'), status user_status.
2. `commun.session` — FK user_id, refresh_token UNIQUE VARCHAR(500), device_id FK, ip_address INET, user_agent, expires_at, revoked_at.
3. `commun.device` — FK user_id, device_type, device_name, push_token VARCHAR(500), push_platform (apns/fcm/web_push), last_seen_at/ip.

### UNIVERS 5 — LA GOUVERNANCE (mémo détaillé)
- **Rôle** : pilier invisible = cadre de légitimité des décisions, infrastructure de participation, mémoire des décisions, gardien des équilibres traditionnels/démocratiques. 4 dimensions : délibérative, représentative, normative, contentieuse. Navigation 5 entrées : Votes en cours, Comités, Décisions, Règlement, Recours + entrée Administration (rôles autorisés).
- **7 modules** : 4.1 Votes et consultations ; 4.2 Comités et conseils ; 4.3 Élections et mandats ; 4.4 Règlement intérieur et statuts ; 4.5 Procès-verbaux et archives de décisions ; 4.6 Assemblées et congrès ; 4.7 Médiation et recours.
- **Cinq niveaux de décision** (configurables par famille) : Consultation (tous membres adultes, aucun quorum, non contraignant) / Vote simple (tous membres adultes, quorum 50 % des votants, majorité simple) / Vote des responsables (chefs de branche + suppléants, quorum 2/3 des chefs, majorité simple) / Vote du conseil (membres du conseil, quorum 2/3, majorité qualifiée 2/3) / Décision du patriarche (unilatérale, pas de quorum/majorité).
- **Paramètres d'un vote** : Type, Sujet, Options (oui/non, choix multiples, libre), Périmètre (famille/branche/comité), Durée (ouverture+clôture), Quorum, Majorité (simple / qualifiée 2/3 / absolue), Anonymat (anonyme / nominatif / semi-anonyme visible par le conseil), Validateur. Déroulement 4 étapes : Ouverture → Expression (2FA obligatoire pour votes contraignants, bulletins chiffrés jusqu'à clôture) → Clôture (agrégation + vérif quorum/majorité) → Publication (avec mention de légitimité). Reçu de vote avec identifiant unique (vérifiabilité sans révéler le choix) ; journal d'audit consultable par le conseil, jamais les bulletins ; mode nominatif semi-anonyme réservé aux votes sensibles (élections, destitutions), visible conseil+patriarche.
- **Égalité** : nouveau vote sous 7 jours ; nouvelle égalité → patriarche tranche (ou conseil selon config). **Vote serré** (écart < 5 %) : recomptage auto, période de contestation 7 jours ouverte à tout votant, éventuel nouveau vote.
- **10 types de comités** : exécutif/Conseil familial (patriarche + chefs de branche + sages cooptés), financier, social, événementiel, jeunesse (18-35 ans), femmes, diaspora (référents par pays), communication, médiation (3-5 membres reconnus sagesse/discrétion), culturel et traditionnel. Composition : président (souvent désigné par patriarche/conseil), secrétaire, 3 à 15 membres (équilibre branches/générations), mandat 2-4 ans renouvelable avec rotation, suppléant. Espace de travail : fil de discussion, agenda, bibliothèque de documents, suivi des décisions, votes internes. Comptes-rendus structurés (date/lieu/présence, ordre du jour, délibérations, motions adoptées, actions qui/quoi/quand, prochaine réunion), validés président+secrétaire. **Comité inactif 6 mois** → signalé au conseil → relancer / fusionner / dissoudre.
- **Types d'élections** : Trésorier (éligible : membre adulte reconnu pour intégrité ; votants : Conseil familial ; mandat 2-4 ans renouvelable), Trésorier adjoint (identique), Chef de branche (votants : membres adultes de la branche ; mandat à vie ou jusqu'à destitution), Patriarche (non élu, désigné par tradition = aîné de la génération régnante, à vie), membres du conseil (2-4 ans), membres de comités (2-4 ans). **Processus en 5 étapes** : Annonce → Candidatures (délai défaut 14 jours ; profil + programme court + soutiens) → Campagne (14 jours défaut) → Scrutin (bulletin secret, 7 jours, 2FA) → Proclamation (résultats + quorum/majorité + validation patriarche ou conseil ; le mandat démarre à la date prévue).
- **Mandats** : titulaire (membre U1), poste, début, fin prévue, validateur, journal des actions marquantes (décisions validées, absences, délégations), motif de fin anticipée (démission, destitution, décès). Un seul titulaire par poste (sauf suppléance explicitement déclarée). **Destitution** : saisine du conseil par ≥ 10 % des membres adultes ou par le patriarche → enquête comité médiation → vote conseil majorité qualifiée 2/3 → validation patriarche éventuelle → notification motivée + droit de recours ; consignée au journal d'audit, mandat archivé en U6. **Transition du patriarche** : enregistrement formel de la désignation, validation conseil + chefs de branche, annonce officielle avec cérémonie protocolaire, transfert des accès/prérogatives ; contestation → comité médiation ; blocage persistant → médiation externe (chef traditionnel / autorité religieuse).
- **Règlement intérieur** : 10 sections type (1 Dispositions générales, 2 Membres, 3 Branches, 4 Instances, 5 Décisions, 6 Finances, 7 Solidarité, 8 Événements, 9 Mémoire et patrimoine, 10 Modifications du règlement). Consultation : table des matières cliquable, recherche plein texte, glossaire (coutumes), renvois entre articles. **Amendement** : proposition (patriarche, conseil, ou ≥ 10 % des membres adultes) → examen rédaction par comité exécutif → vote conseil majorité qualifiée 2/3 (ou AG selon règlement) → publication avec mention des modifications ; chaque version archivée (historique consultable/comparable). **Conformité** : chaque décision (vote, motion, élection) rattachée à un article du règlement ; non-conformité → suspension + régularisation. Conflit tradition/règlement : section dédiée aux traditions (même statut que les articles écrits), arbitrage du patriarche, décision d'arbitrage archivée (jurisprudence).
- **PV** : 5 types — réunion de comité (rédacteur : secrétaire du comité, validation : président), réunion de branche (secrétaire de branche / chef de branche), conseil (secrétaire du conseil / patriarche), assemblée générale (secrétaire général / patriarche), congrès (secrétaire général / patriarche + conseil). Structure : en-tête (instance, date, lieu, présents/excusés/absents), ordre du jour, déroulé, décisions (motions+votes+résultats), actions (responsables+échéances), clôture + signatures numériques. Cycle : Brouillon (délai défaut 7 jours après réunion) → Relecture (président) → Validation (signatures numériques président+secrétaire) → Publication. **PV validé = immutable ; toute correction par avenant** (motif + mêmes autorités). Recherche plein texte, filtres (instance/date/type/mots-clés), renvois entre PV connexes, export PDF. Tous les PV validés archivés dans U6.
- **Assemblées et congrès** : cycle = Convocation (préavis défaut 30 jours AG, 90 jours congrès) → Ordre du jour (motions des membres ajoutables dans un délai défini) → Documents préparatoires (rapports trésorier/conseil/comités) → Déroulé (ouverture patriarche, rapports, débats, votes, motions, clôture) → PV → Archivage U6. - **Recours** (5 types) : contestation d'une décision (destinataire comité médiation, délai 30 jours après décision), recours contre un chef de branche (conseil familial, 30 jours), recours contre le trésorier (conseil + comité médiation, immédiat), recours contre le patriarche (conseil familial élargi, exceptionnel), recours électoral (comité médiation + conseil, 7 jours après proclamation). **Procédure** : Dépôt (formulaire + motif + pièces) → Recevabilité (comité médiation, 7 jours ; irrecevable = rejet motivé) → Instruction (auditions, pièces, experts) → Décision (comité médiation, 14 jours, motivée, transmise aux parties et au conseil) → Appel (conseil puis patriarche en dernier ressort). Confidentialité par défaut (accès : parties + comité médiation + conseil ; publication interdite sauf décision contraire du patriarche). Journal des recours (statuts : en cours, tranché, en appel) pour détecter les patterns. **Recours contre le patriarche** : 2 cas seulement (décision manifestement contraire au règlement ; manquement grave à l'éthique — détournement, abus, inaptitude) ; saisine ≥ 20 % des membres adultes ou comité médiation → concertation élargie (chefs de branche, sages) → décision du conseil élargi à la majorité 2/3 → éventuel patriarche intérimaire + procédure de transition. **Lien U3** : même comité médiation, champs distincts (U3 = conflits de solidarité ; U5 = conflits de gouvernance), dossiers/journaux/procédures séparés.

Phase 3 (mois 16-22) : IA participation (suggestions quorums), votes hybrides multi-fuseaux, conformité automatique, médiation assistée, notifications vocales (rappels votes aux aînés), gouvernance multi-famille — sortie : abstention ≤ 20 %, contestations ≤ 5 %, adoption ≥ 90 %.
- **Écrans clés** : Consultation en cours (format ID VOTE-2026-008 ; périmètre 220 votants ; quorum affiché ; résultats après clôture) ; Comité de travail (composition, mandats 2025-2027, prochaine réunion, derniers comptes-rendus PV-2026-014…, actions en cours) ; Élection trésorier (statut campagne J-3, candidats avec programmes+soutiens, quorum 2/3 conseil=8 votants, majorité absolue 50 %+1, 2FA) ; Règlement intérieur (v3.2, historique des versions avec dates) ; PV de congrès (PV-2026-003, présentiel+visio 198/247, motions avec pour/contre/abstentions, liens articles du règlement, signatures numériques, statut « Immutable — Archivé U6 »).
- **Risques & mitigations** : abstention (simplicité « un tap pour voter », rappels J-7/J-1/jour même, publication de l'impact, obligation de justifier une abstention pour votes contraignants si besoin) ; contestation de légitimité (traçabilité, recours, publication résultats) ; conflits de pouvoir (procédure formelle, secret des bulletins, arbitrage patriarche) ; traditionalisme (configurabilité, hybridité, accompagnement, cérémonies protocolaires maintenues) ; fraude électorale (2FA, chiffrement, journal d'audit, contestation 7 jours) ; confidentialité des recours (accès restreint, journal des consultations, formation au secret) ; dérive technocratique (notifications vocales, référent humain, motions lues à voix haute).

### UNIVERS 6 — LA MÉMOIRE (mémo détaillé)
- **Rôle** : gardien du patrimoine immatériel = réceptacle unique des archives des autres univers (archivage auto), gardien de la mémoire des ancêtres (urgence : génération régnante 70-90 ans, derniers à avoir connu les fondateurs), conservatoire du patrimoine immatériel, infrastructure de transmission intergénérationnelle. 4 dimensions : documentaire, visuelle, orale, patrimoniale. Navigation 5 entrées : Bibliothèque, Albums, Anciens, Histoire, Traditions + Recherche globale plein texte.
- **7 modules** : 4.1 Bibliothèque documentaire ; 4.2 Albums photo et vidéo ; 4.3 Mémoire des anciens ; 4.4 Histoire familiale ; 4.5 Archives d'événements et de décisions ; 4.6 Patrimoine et traditions ; 4.7 Recherche et exploration.
- **Bibliothèque documentaire** (coffre-fort numérique) — types de documents avec source/confidentialité : Statuts et règlement (U5, public familial) ; PV assemblées et congrès (U5, public familial) ; PV conseil et comités (U5, restreint conseil+comité) ; Bilans financiers annuels (U4, public familial) ; Contrats et actes notariés (saisie manuelle, restreint conseil+ayants droit) ; Correspondances officielles (saisie manuelle, restreint conseil) ; Rapports de comités (U5, public) ; Documents d'identité familiale (U1, restreint membre+conseil). Organisation : Type → Année → Instance émettrice → Version (historique complet, comparaison de versions). **3 niveaux d'accès** : publics familiaux / restreints (conseil, comité médiation, ayants droit) / confidentiels (patriarche + comité médiation seulement, avec journal des consultations). **Conservation longue durée** : triple stockage (serveur principal + sauvegarde externalisée + archive froide), formats durables (PDF/A ISO 19005 pour textes, JPEG/TIFF pour images), migration périodique tous les 5 ans, horodatage cryptographique. **Document sensible** : statut « scellé » (masqué jusqu'à date/événement défini, ex. décès du testateur), accès conditionnel (validation patriarche + comité médiation), journal des consultations consultable par le concerné ou ses ayants droit.
- **Albums** : génération automatique à la clôture d'un événement U2 (liés par identifiant partagé, héritent des métadonnées : date, lieu, branche, participants) ; contributions collaboratives. **Tagging automatique** : reconnaissance faciale (à partir du registre U1, avec proposition de tags), détection de lieu (EXIF ou reconnaissance visuelle), détection de date (EXIF ou événement rattaché), tags manuels. Modération par le référent de l'événement ; **droit à l'image** (retrait sans justification) ; témoignages par photo ; photos emblématiques désignées en tête d'album. Narration : texte d'introduction, légendes, témoignages, bilan (lien U2/U3/U4). Préservation : format original conservé + versions compressées pour consultation, triple stockage, migration 5 ans. Photo offensante/blessante : signalement par tout membre → retrait temporaire immédiat → examen référent + comité médiation → décision définitive (retrait / conservation restreinte / conservation publique avec avertissement de contexte) + journal.
- **Mémoire des anciens** : objectif couverture interviews 50 % des anciens 60+ l'an 1, 90 % à 3 ans ; priorisation par âge et état de santé. **Interviews** : guide d'entretien thématique (origines, enfance, vie adulte, mariage, enfants, carrière, leçons de vie, message aux jeunes générations), enregistrement audio+vidéo via mobile, transcription automatique (reconnaissance vocale) + correction manuelle, indexation (thèmes, noms cités, lieux), chapitres navigables ; rattachées au membre U1, branche, génération ; consultables par tous sauf restriction demandée par l'ancien. **Biographies** structurées : fiche d'identité (nom, dates, lieu de naissance, filiation, profession, famille), parcours de vie, contributions à la famille, anecdotes et souvenirs, message aux générations futures ; rédigées par l'ancien, un proche ou le comité culturel ; validées par l'ancien si vivant. **Récits collectés** : origines (mythes fondateurs, migrations), événements marquants, traditions, proverbes et sagesses. Formats : MP3/WAV audio, MP4/MOV vidéo, PDF/A texte. **Restriction temporaire** : un ancien peut imposer une diffusion posthume ou après un délai. Cas : décès avant interview → collecte posthume auprès des proches/enfants/amis + page mémoire + hommage au congrès suivant.
- **Histoire familiale** : **frise chronologique** (date exacte ou approximative, lieu, description courte, type ∈ {naissance, décès, mariage, congrès, achat de terrain, migration, réussite, épreuve}, liens vers archives ; navigable, filtrable par type/branche/période). **Récits fondateurs** (origine du nom, migration, installation, fondation) validés par le comité culturel, évolutifs. **Lignée des patriarches** : fiche par patriarche (dates naissance/décès, durée du patriarcat, décisions marquantes, événements de son époque, portrait, témoignages, lien PV d'intronisation). **Grandes dates** (classement par importance, pas chronologique) : fondation, première acquisition de terrain, premier congrès, première diaspora, première femme diplômée, premier centenaire. **Carte interactive** : village d'origine, résidences historiques, terrains/propriétés, lieux des grands événements, sépultures des ancêtres. **Mémoire conflictuelle** : plusieurs versions d'un même récit avec sources mentionnées, version officielle validée par le comité culturel + alternatives conservées, arbitrage comité médiation en cas de conflit ouvert.
- **Archives d'événements et de décisions** : archivage automatique déclenché par clôture en U2/U3/U4/U5 — U2 : dossier événement (métadonnées, programme, participants, contributions, album, bilan) ; U3 : dossier solidarité (métadonnées, collecte, dépenses, justificatifs, suivi, bilan) ; U4 : exercice annuel (bilan, compte de résultat, balance, rapports d'audit) ; U5 : PV validé + décision adoptée (PV, motions, votes, résultats, signatures). Archivage immédiat, aucune clôture n'échappe à l'archive. **Cross-références** entre archives (congrès U2 ↔ PV U5 ↔ bilan U4 ↔ dossiers U3 ; décès U2 ↔ solidarité U3 ↔ album U6 ↔ biographie U6). Conservation indéfinie ; jamais supprimées sauf décision exceptionnelle du conseil (ex. effacement de contenu diffamatoire sur décision de justice). **Amendement d'archive** : proposition par membre autorisé → validation conseil → avenant joint (archive originale jamais modifiée).
- **Patrimoine et traditions** — 7 types : Coutumes et rites (dot, levée de deuil, purification, rites funéraires) ; Recettes (ndolé de la famille, sauce gombo, poisson braisé) ; Chansons et musiques ; Proverbes et sagesses ; Lieux symboliques (village d'origine, arbre à palabres, case des ancêtres, sources sacrées) ; Patrimoine linguistique (mots, expressions, comptines) ; Savoir-faire (poterie, vannerie, médecine traditionnelle, agriculture). Documentation structurée : description/contexte, origine, règles et déroulement, ingrédients et recette, paroles et mélodie, photos/vidéos, témoignages des gardiens, lien avec les événements. Transmission : fiches pédagogiques, vidéos tutorielles, sessions de transmission aux congrès, quiz et jeux. **Tradition restreinte** (rites initiatiques, savoirs sacrés) : périmètre défini par le patriarche, documentation allégée pour non-initiés / complète pour initiés. **Tradition éteinte** : statut dédié, documentation maximale à partir des souvenirs, proposition de relance possible. **Patrimoine linguistique menacé** (medumba, fe'fe', ghomala') : enregistrements + traduction, glossaire, vidéos pédagogiques, partenariats institutions linguistiques.
- **Recherche et exploration** : moteur plein texte (simple avec autocomplétion ; avancée avec filtres type/date/branche/auteur/lieu ; par membre ; par événement ; suggestions), résultats triés pertinence + extraits surlignés ; navigation temporelle (frise par décennie, sélection par année, comparaison de périodes) ; cartes et graphes (carte des lieux, graphe des relations, carte de la diaspora dans le temps) ; suggestions personnalisées (branche, ancêtres, contributions, historique de consultation). Recherche infructueuse → synonymes/orthographes proches, invitation à contribuer, contact comité culturel.
- **Modèle de données (7 entités)** : Document (type, titre, version, date, auteur, URL, droits d'accès) ; Album (événement, contributeurs, photos, narration, statut) ; Témoignage (membre, type, format, transcription, thèmes, durée) ; ÉvénementHistorique (date, lieu, type, description, liens vers archives) ; Archive (univers source, identifiant source, date de clôture, contenu) ; Tradition (type, description, origine, gardiens, statut) ; Index (type, valeur, références vers archives). Relations : Document → univers source U1-U5 + instance émettrice ; Album → événement U2, contient photos/vidéos ; Témoignage → membre U1, indexé par thèmes ; ÉvénementHistorique cross-référencé avec archives et témoignages ; Archive → univers source, cross-référencée ; Tradition → gardiens (membres U1) + événements de pratique ; Index relie les éléments (ex. toutes les archives mentionnant un membre). Intégrité : jamais de suppression (avenants) ; document scellé → autorisation explicite ; tradition restreinte → membres autorisés ; témoignage restreint → respect du délai défini par l'ancien ; toute consultation de document sensible journalisée.
- **Règles de gestion R1-R15** : R1 archivage auto de tout dossier clôturé U2/U3/U4/U5 ; R2 jamais de suppression (avenants) ; R3 triple stockage sur supports indépendants ; R4 formats durables (PDF/A, JPEG, MP3, MP4) ; R5 migration des formats tous les 5 ans ; R6 horodatage cryptographique ; R7 droits d'accès par type et rôle ; R8 droit au retrait d'une photo où l'on apparaît ; R9 interviews priorisées par âge et santé ; R10 témoignage restreint à diffusion posthume possible ; R11 traditions restreintes visibles des autorisés seulement ; R12 journal des consultations des documents sensibles consultable par le concerné ; R13 sauvegarde externe trimestrielle ; R14 comité culturel responsable de la collecte ; R15 toute modification d'archive tracée (auteur, motif, validateur).
- **Cas limites** : droit à l'oubli (demande examinée par le comité médiation ; retrait des informations nominatives mais archive anonymisée conservée — équilibre dignité vs mémoire) ; contenu offensant (procédure de signalement commune) ; mémoire conflictuelle (versions multiples) ; perte de données (restauration depuis sauvegardes trimestrielles, audit d'étendue, communication transparente, plan de prévention ; tests de restauration ≥ 1/an ; plan de continuité ; assurance cyber-risque optionnelle).
- **KPIs an 1** : archivage automatique 100 % ; interviews anciens 60+ ≥ 50 % ; couverture documentaire ≥ 80 % ; événements clôturés avec album ≥ 10 photos ≥ 70 % ; fréquentation archives ≥ 30 % des membres/mois ; contributions collaboratives ≥ 20/mois ; satisfaction transmission ≥ 4/5 ; traditions documentées ≥ 30 ; disponibilité service ≥ 99,5 % ; sauvegardes externes ≥ 4/an (trimestrielles).
- **Roadmap** : Phase 1 MVP (mois 8-12) : bibliothèque documentaire avec versioning, albums photo (tagging manuel, contributions), archivage automatique U2-U5, recherche plein texte, triple stockage — sortie : 100 % archivé auto, ≥ 80 % documents, 70 % événements avec album. Phase 2 (mois 13-17) : mémoire des anciens (interviews, transcription, indexation), histoire familiale (frise, récits fondateurs, lignée patriarches), patrimoine, carte interactive, tagging automatique (reconnaissance faciale + lieu), cross-références — sortie : ≥ 50 % anciens interviewés, ≥ 30 traditions, ≥ 4/5. Phase 3 (mois 18-24) : IA transcription multilingue (français + langues locales), exploration visuelle (graphes, navigation temporelle avancée), suggestions personnalisées, vidéos pédagogiques, partage élargi aux familles alliées (sur autorisation), conservation longue durée (partenariats institutionnels) — sortie : ≥ 90 % anciens interviewés, fréquentation ≥ 30 %/mois, ≥ 20 contributions/mois.
- **Écrans clés** : Bibliothèque documentaire (sections statuts/PV/bilans/contrats ; testament « scellé » visible) ; Album d'événement (EVT-2026-008, 187 photos + 12 vidéos, narration signée, photos emblématiques, témoignages, bilan 6 000 000 FCFA / 198 invités) ; Interview d'ancien (Témoignage Papa Jean 85 ans, 2h47, 9 chapitres horodatés, index personnes/lieux/thèmes, transcription) ; Frise historique (1920 fondation → 2026 congrès à venir, proposition d'ajout) ; Moteur de recherche (résultats mixtes PV/album/témoignage/tradition avec extraits).
- **Risques & mitigations** : perte de données (triple stockage, sauvegarde externe trimestrielle géographiquement distante, tests annuels, plan de continuité, assurance cyber) ; obsolescence numérique (formats durables, migration 5 ans, veille, documentation des formats) ; confidentialité (gradation des droits, statut scellé, journal des consultations, formation) ; coût du stockage (versions compressées en consultation + originaux en archive froide, rétention configurable — suppression versions intermédiaires après 5 ans, coût intégré à l'abonnement familial U4, mutualisation multi-familles) ; manipulation de l'histoire (pluralité des sources, conservation des versions alternatives, comité culturel multi-branches, droit de contestation) ; excès de nostalgie (articulation mémoire ↔ projet, sessions de transmission active, invitations à contribuer).

### UNIVERS 7 — LE RÉSEAU (mémo détaillé)
- **Rôle** : 7e et dernier univers — répertoire des ressources familiales, infrastructure de l'entraide, cadre du mentorat intergénérationnel, porte d'entrée du réseau diaspora. 4 dimensions : compétences, entraide, transmission, opportunités. Cœur commun : **la mise en relation (consentement + respect)** — « la famille devient un réseau sans devenir un marché ». Navigation 5 entrées : Compétences, Entraide, Mentorat, Opportunités, Diaspora + Messagerie globale.
- **7 modules** : 4.1 Répertoire des compétences ; 4.2 Entraide et services ; 4.3 Mentorat intergénérationnel ; 4.4 Opportunités professionnelles et d'affaires ; 4.5 Réseau diaspora ; 4.6 Recommandations et réputation ; 4.7 Messagerie et mises en relation.
- **Répertoire des compétences** : 12 catégories configurables — Santé (médecine, pharmacie, infirmerie, psychologie), Droit (avocat, notaire, juriste, magistrat), Finance (expert-comptable, banquier, assureur, contrôleur de gestion), Ingénierie (génie civil, informatique, électronique, mécanique, agriculture), Éducation, Commerce (import-export, marketing), Artisanat (menuiserie, maçonnerie, couture, cuisine, poterie), Administration (RH, secrétariat, logistique), Communication (journalisme, design, audiovisuel), Social (travail social, médiation), Art (musique, danse, théâtre, arts plastiques), Agriculture (cultures, élevage, agroforesterie). **Profil de compétences** : métier principal, expertises, expérience (années + parcours), formation (diplômes, certifications), disponibilités (conseil ponctuel, mentorat, mission rémunérée), visibilité (public familial / restreint « réseau de confiance » / privé). Auto-validated par le membre ; mention **« profil vérifié »** si le chef de branche confirme (non obligatoire). Recherche : mot-clé (autocomplétion), catégorie, branche, localisation, disponibilité ; tri pertinence avec mise en avant des vérifiés/actifs. **Demande d'aide** : description, domaine, urgence (immédiate / court terme / moyen terme), modalité (conseil ponctuel, accompagnement, mission), rémunération (bénévole / frais remboursés / rémunérée). Fausse expertise : profil vérifié + recommandations + signalement (comité médiation) → retrait du profil si avéré.
- **Entraide et services** : 8 types — hébergement, transport, conseil pratique, soutien administratif (remise de documents, traduction, légalisation), garde d'enfants, accompagnement (médical, rendez-vous), logistique (prêt de matériel, déménagement), soutien émotionnel (deuil, stress). Proposition : type, conditions (durée, fréquence, limites), zone géographique, disponibilité (calendrier), restrictions éventuelles. Demande : diffusion ciblée (localisation, type), visible au tableau de bord, suivi jusqu'à résolution (satisfaite, annulée, expirée) ; urgences possibles (« hébergement pour cette nuit »). **Suivi** : mise en relation (messagerie interne) → confirmation par les deux parties (date, lieu, conditions) → réalisation → **évaluation mutuelle** → archivage dans l'historique du réseau. **Prévention de l'épuisement** : plafond configurable de demandes/mois (défaut 5), suivi du taux d'acceptation avec alerte de sur-sollicitation, mise en pause (« indisponible pour 1 mois »). **Exploitation** : suivi du ratio demandes/rendus par membre, alerte comité médiation en cas de déséquilibre significatif, médiation, en dernier recours restriction des possibilités de demande de l'exploiteur.
- **Mentorat** : 5 programmes — court (3 mois, 1 rencontre/mois, conseil sur projet précis), annuel (12 mois, 1 rencontre/mois, carrière ou études), de vie (durée non définie, au cas par cas, transmission de sagesse), de projet (durée du projet, variable, entrepreneurial ou personnel), diaspora (6 mois, 1 rencontre/mois, expatriation). Profil mentor : domaine d'expertise, type de mentorat (carrière, études, entrepreneuriat, vie personnelle), disponibilité (nb mentorés, fréquence), préférences (branche, mentoré féminin…). Profil mentoré : besoin, domaine, préférences, engagement. **Appariement** : recommandations automatiques (domaines, branches, préférences), demande manuelle vers un mentor précis, validation du mentor (accepter/refuser avec motif), validation du chef de branche pour mentorés mineurs. **Suivi** : plan de mentorat (objectifs, jalons, fréquence), compte-rendu court par le mentor après chaque rencontre (visible du mentoré), **évaluation croisée à mi-parcours (3 mois)**, évaluation finale, archivage du mentorat dans U6. **Plafond : 3 mentorés simultanés par mentor (configurable)** ; pause possible (« plus disponible pour 6 mois ») ; médiation en cas de conflit mentor-mentoré. Anciens 60+ comme mentors de vie : valorisation spécifique (mention, reconnaissance publique), accompagnement prise de RDV, lien avec les interviews U6.
- **Opportunités professionnelles et d'affaires** : 8 types — offre d'emploi, offre de stage, opportunité d'affaires (associé, partenariat, marché), appel d'offres, projet familial (terrain, construction, événement), investissement (club d'investissement), formation, mission ponctuelle rémunérée. Publication : type, intitulé/description, compétences requises, localisation (présentiel/distanciel/hybride), rémunération, échéance (date limite), contact (interne/externe), confidentialité (« ne pas diffuser hors de la famille »). **Modération a priori** par le comité communication (pas de fraude ni discrimination). Candidat : postuler / demander des infos / recommander un autre membre ; suivi jusqu'à l'issue (embauche, refus, abandon). **Coentreprises et projets collectifs** : coentreprise (société multi-membres avec répartition capital/responsabilités), projet immobilier en indivision, projet événementiel économique, investissement collectif — exigent accord écrit, répartition des gains et pertes, clause de sortie ; l'app fournit des modèles d'accord et un suivi structuré. Fraude : modération a priori, signalement → retrait temporaire, enquête comité médiation, fraude avérée = retrait définitif + sanction du publiant + communication à la famille. Conflit d'intérêts : transparence des liens familiaux (publiant identifié, candidats identifiés), déclaration du publiant si lien avec un candidat, médiation en cas de contestation.
- **Réseau diaspora** : **relais diaspora par pays** (un minimum par pays où réside au moins un membre), désigné par le conseil sur proposition du comité diaspora, **mandat 2-4 ans renouvelable**. Missions : accueillir les nouveaux arrivants (contact dans les 30 jours suivant l'installation), diffuser les informations pratiques, faciliter les rencontres, remonter les besoins au conseil, coordonner les actions solidaires. **Accueil** : le membre signale son arrivée → notification du relais → mise en relation → guide d'accueil → rencontre (présentiel ou visio) planifiée dans les 30 jours. **Fiche pays** (évolutive, alimentée par le relais et les membres) : logement, santé, école, administration (titre de séjour, travail, fiscalité), transports, vie pratique (banques, culture, culte), retour au pays. **Entraide administrative** : conseils d'expérience, accompagnement physique aux rendez-vous sensibles, traduction, légalisation. **Retour au pays** : préparation (réinstallation, logement, emploi), mise en relation professionnelle au Cameroun, suivi pendant les 6 mois post-retour (« choc inverse »). Membre diaspora en difficulté : signalement relais + comité médiation → évaluation → coordination avec U3 (aide financière éventuelle) → suivi jusqu'à résolution.
- **Recommandations et réputation** : 5 types — d'expertise (confirme une compétence), de service (évalue une entraide), de mentorat (fin de programme), professionnelle (recommande pour une opportunité), de relais (qualité de l'accueil diaspora). Contenu : note 1-5 étoiles, commentaire (recommandé), contexte (type de relation, durée), auteur (**doit avoir effectivement interagi** avec le recommandé — mentorat enregistré, entraide réalisée). Publiques par défaut ; confidentialité de l'auteur possible (utile pour retours négatifs/sensibles). **Anti-abus** : vérification de l'interaction réelle, plafond de 5 recommandations par membre et par mois, signalement → comité médiation, retrait + sanction si abus. **Valorisation** : badges (« Mentor actif », « Membre recommandé », « Relais diaspora », « Expert vérifié »), mise en avant en recherche, reconnaissance publique au congrès annuel (rapport moral du patriarche). **Droit de refus** : le recommandé peut refuser une recommandation dans les 7 jours → suppression sans trace publique + journal des refus (comité médiation).
- **Messagerie et mises en relation** : identité vérifiée (profil U1, pas de pseudonymat), conversations privées chiffrées **non accessibles au conseil** (sauf signalement + enquête du comité médiation), historique conservé, notifications push/SMS/e-mail selon préférences, pièces jointes (CV, portfolio, photos). **Demande de contact** : motif (aide, mentorat, opportunité, autre), message d'introduction, contexte (référence compétence/opportunité) ; accepter/refuser/ignorer ; en cas de refus aucun message n'est envoyé à l'auteur (anti-harcèlement). Modération a posteriori sur signalement : examen comité médiation → suppression + sanctions graduées (avertissement, suspension temporaire, exclusion du réseau) + journal. Blocage possible entre membres à tout moment ; masquage des coordonnées possible (messagerie interne seule). **Anti-harcèlement** : plafond de 3 messages sans réponse avant blocage automatique, signalement automatique si répétition, charte du réseau signée par tout membre, sanctions graduées. Harcèlement avéré : signalement → examen immédiat **sous 48 h** → protections immédiates (blocage par la victime, suspension temporaire) → enquête approfondie → sanction définitive → dépôt de plainte éventuel. Tolérance zéro, protection renforcée des femmes et des jeunes.
- **Modèle de données (7 entités)** : Compétence (membre, catégorie, intitulé, expérience, visibilité) ; Service (type, proposant, demandeur, statut, évaluation) ; Mentorat (mentor, mentoré, programme, début, fin, statut) ; Opportunité (type, intitulé, description, échéance, contact) ; RelaisDiaspora (pays, relais, mandat, membres dans le pays) ; Recommandation (auteur, destinataire, type, note, commentaire) ; MiseEnRelation (demandeur, destinataire, motif, statut). ### STRATÉGIE P2P (mémo détaillé — MD v1.0, Octobre 2026, 656 lignes, « Changement architectural majeur »)
- Pourquoi : modèle WhatsApp — l'app est un RELAIS entre téléphones, jamais un stockage. Contexte : économie drastique (pas de S3 média ni bande passante), confidentialité (fichiers sous contrôle du propriétaire), alignement mental utilisateur. Sans P2P : 1 000 familles = 5-15 To/an = 5-15 M FCFA/an de S3 ; avec P2P ≈ 0 (< 1 Go/famille/an de structuré).
- Principe : fichiers média (photos 2-5 Mo, vidéos 50-200 Mo, audio, voice notes, docs, messages) restent sur le téléphone de l'EXPÉDITEUR ; seul un MANIFESTE (nom, type, taille, checksum SHA-256, expéditeur, statut) va au cloud. Expéditeur supprime → manifeste « deleted », nouveaux téléchargements bloqués, mais les caches existants des destinataires restent consultables indéfiniment. Expéditeur hors-ligne → « temporairement indisponible » + alerte « Préviens-moi quand disponible ».
- Techno : WebRTC DataChannel (chiffré DTLS/SRTP de bout en bout), STUN public Google, TURN coturn (2 vCPU/4 Go, ~20 000 FCFA/mois, requis dans 10-20 % des cas, transit sans stockage) ; serveur de signalisation Node.js + Socket.io sur Cloudflare Workers ou petit serveur (SDP/ICE, présence, relais manifestes, files d'attente) ; cache local chiffré (SQLCipher, répertoire privé). Partage en cascade optionnel torrent-like (cascade_enabled default TRUE : un destinataire en cache devient source secondaire).
- Cloud conservé (texte structuré, coût négligeable) : registre U1, événements U2, dossiers U3, écritures U4, votes/PV U5, manifestes, notifications, règlement, MESSAGES CHAT (0,2 Ko, livraison différée, recherche Elasticsearch, conservation 90 j puis archive froide, suppression « pour tous » < 1 h, ✓✓).
- Exceptions archivage cloud EXPLICITE (is_archived=true, jamais accidentel, notif au propriétaire + trace audit) : interviews d'anciens (comité culturel — l'ancien peut décéder), justificatifs > 500 000 FCFA (trésorier), actes notariés/testaments (patriarche/conseil), PV congrès PDF signé (secrétaire), photos emblématiques (référent).
- Schéma PostgreSQL mis à jour : `commun.file` REMPLACÉE par `commun.file_manifest` (availability_status ENUM available/offline/deleted/archived, s3_bucket/s3_key, cascade_enabled, checksum_sha256) ; NOUVELLES `commun.file_download` (status pending/downloading/completed/failed/expired ; source sender/cascade/cloud ; is_pinned) et `commun.presence` (online/away/offline) ; FK mises à jour : vie_familiale.photo, album.cover_manifest_id, solidarite.solidarity_expense, finances.payment, finances.accounting_entry, memoire.testimony/document.
- Cache téléphone : épinglés « Conserver » jamais supprimés ; récents < 30 j et fréquents prioritaires ; anciens > 90 j non consultés et jamais consultés supprimés en premier ; alerte à 80 % de la limite (défaut 2 Go), nettoyage auto à 95 % ; limites 500 Mo/1/2/5 Go/illimité ; conservation 30/60/90 j.
- Sécurité : chiffrement DTLS en transit (signalisation et TURN aveugles), répertoire privé chiffré destinataire (hors galerie sauf « Exporter »), authentification mutuelle des pairs + permissions RBAC via serveur, validation checksum SHA-256 post-téléchargement (rejet si mismatch).
- Cas limites : téléphone perdu (manifestes « perdus », récupération via caches) ; vidéo > 200 Mo (chunks, pause/reprise, checksum par chunk) ; congrès rural SANS Internet = mode LAN Wi-Fi direct/Bluetooth ; archivage interview = upload S3 + triple stockage U6.
- Coûts Phase 3 révisée : S3 -99 % (~50 Go/an archives), bande passante -95 % (~100 Go/mois), +40 K FCFA/mois (signalisation+TURN) ; total 11,8-39,3 M FCFA/mois, économie nette 200 K-2,7 M FCFA/mois. ⚠️ Le doc cite ECS/RDS/Redis/Elasticsearch (AWS) alors que le projet cible Cloudflare — à harmoniser.
- 12 nouveaux scénarios de test P2P-01..P2P-12 (transfert 5 Mo < 30 s, TURN sans stockage, suppression, cascade, checksum, nettoyage 95 %, archivage cloud, LAN, reprise chunks, DTLS, vidéo 200 Mo < 5 min). Prochaines étapes : mettre à jour archi technique + schéma + plan de test, implémenter signalisation et TURN dès Phase 1.

### UNIVERS 1 — LA FAMILLE (mémo détaillé)

**Méta** : Version 1.0, Septembre 2026, statut "Pour validation". U1 = socle fondateur non négociable, à livrer en premier. Familles cibles 80–400 membres, pilote 150–300. **7 modules** (cœur = Registre des membres, les 6 autres en sont des vues/extensions) :
- 4.1 Registre familial : fiche membre = unité atomique du système. 9 blocs (le texte dit "six blocs" mais la table en liste 9) avec visibilité par défaut : Identité (nom, prénom, surnom, sexe, date+lieu naissance — publique familiale), Filiation (père, mère, parents adoptifs — publique), Appartenance (branche, sous-branche, génération — publique), Situation (état civil célibataire/marié/veuf/divorcé, conjoint(s), enfants — publique), Contact (téléphone, e-mail, ville, pays, adresse postale — publique sauf adresse précise restreinte), Profession (métier, employeur, compétences, disponibilités — publique, détails restreints), Santé (groupe sanguin, allergies, contacts d'urgence, personne à prévenir — RESTREINTE comité médiation uniquement), Préférences (langue, fuseau horaire, canal de notification préféré — PRIVÉE), Mémoire (photo, biographie courte, anecdotes — publique). - 4.2 Arbre généalogique interactif : graphique ancêtres en haut/descendants en bas ; nœud=membre, lien=filiation OU union (date mariage, éventuellement dot) ; unions polygamiques = plusieurs liens d'union depuis le nœud père. Cas limites filiation : père inconnu (rattaché à mère+sa branche, champ père vide + mention explicite), adoption plénière (liens bio masqués en vue publique, conservés en base), filiation par alliance (tuteur / "parent d'élevage" ≠ père biologique), conjoints externes dans l'arbre sans ascendance développée.
- 4.3 Branches et sous-branches : branche = descendants d'un ancêtre commun (fils/fille du fondateur) ; typiquement 4–8 branches principales ; sous-branches = descendants des petits-enfants. Hiérarchie arborescente Famille (racine) → Branches principales → Sous-branches. Tout membre vivant rattaché à exactement UNE branche principale (+ sous-branche éventuelle) ; règle filiation paternelle par défaut, ajustable par décision du conseil. Chef de branche (généralement aîné des descendants masculins de la génération en exercice, variable selon traditions) : valide inscriptions de sa branche, représente au conseil, consulté, reçoit notifications critiques (décès, maladie grave) ; peut désigner un suppléant ; désignation formalisée par patriarche/conseil avec trace (date, décision, validateur). - 4.4 Rôles et gouvernance minimale : 5 niveaux — Patriarche/Matriarche (aîné de la génération régnante ; arbitre final, valide grandes décisions, représente la famille) ; Conseil familial (chefs de branche + sages cooptés ; vote décisions importantes, arbitre conflits, valide règlement intérieur) ; Chef de branche ; Membre adulte (18+) ; Membre junior (<18 : vue filtrée, pas de vote, pas de cotisation). Matrice de permissions : consulter registre complet (Patriarche Oui / Conseil Oui / Chef sa branche+vue publique / Adulte vue publique / Junior vue filtrée) ; ajouter un membre = chef de branche (sa branche) seul, patriarche valide seulement ; valider ajout = patriarche+conseil+chef(sa branche) ; marquer décès = chef(sa branche), membres "signalent", patriarche valide ; modifier sa fiche = tous (champs personnels) ; créer un vote = patriarche/conseil/chef(sa branche) ; participer vote = tous sauf junior (selon périmètre) ; consulter trésorerie = patriarche/conseil, chef (agrégat sa branche), adulte (vue agrégée), junior non. Destitution : workflow dédié = justification + délai de réflexion + vote à majorité qualifiée, consignée à l'audit.

Les annonces critiques court-circuitent les préférences de canal. Fuseaux horaires respectés (notification différée à heure raisonnable), sauf décès = immédiat quelle que soit l'heure. Anti-saturation : au-delà de 5 notifications/jour (défaut), les non-critiques sont regroupées en digest quotidien.

### UNIVERS 3 — LA SOLIDARITÉ (mémo détaillé)

**Positionnement** : « le cœur battant » de l'app, univers le plus sensible. Remplace la solidarité réactive/opaque par un protocole transparent, traçable et équitable. Prérequis : U1 (membres/branches/rôles), U2 (événements). Dépendances : U4 (caisse, Mobile Money — flux financiers), U6 (archivage des dossiers clôturés), U2 (déclenchement auto via événements M1-M6).

**3 dimensions** de toute situation : émotionnelle (portée U2), financière (cœur U3, lien U4), organisationnelle (U2 + répartition U3). 5 questions opérationnelles auxquelles tout membre doit répondre (solidarités en cours ?, collecté/reste ?, ma contribution ?, dépenses+justificatifs ?, à qui m'adresser ?).

**Objectifs année 1** (famille pilote 150–300 membres) : déclenchement dossier ≤ 4 h ; participation ≥ 70 % ; 80 % de la cible atteinte ≤ 7 j ; dépenses justifiées 100 % ; clôture ≤ 30 j ; satisfaction bénéficiaires/contributeurs ≥ 4/5 ; contestations ≤ 2/an ; aides sociales versées à temps ≥ 95 % ; 0 fuite d'info sensible.

**7 modules** autour du Dossier de solidarité (unité atomique) :
1. **4.1 Dossier de solidarité** — Créé AUTO (règle) ou manuel (exception). Déclenchement par événement U2 : Décès (M1) = auto immédiat, public familial ; Maladie grave (M2) = auto sur validation chef de branche, restreint (branche+conseil) ; Accident (M3) = idem M2 ; Hospitalisation (M4) = auto si durée > 7 j, restreint ; Sinistre (M5) = auto immédiat, public familial ; Difficultés particulières (M6) = manuel uniquement, confidentiel (médiation+conseil). Anatomie 7 sections : métadonnées (bénéficiaire, nature, gravité, branche, dates) ; comité de soutien (référent, membres, validateur=chef de branche) ; collecte (cible, contributions, dépenses, solde — lien U4) ; suivi (étapes, jalons, visites, messages) ; répartition (bénéficiaires finaux, montants, modalités) ; justificatifs ; clôture (bilan, remerciements, archivage U6). **Cycle de vie 5 états** : Ouvert → Collecte en cours → Utilisation → Clôture proposée → Clôturé (validation conseil + archivage U6). Clôture impossible sans bilan financier complet + justificatifs de toutes les dépenses. Lien U2 par identifiant partagé (format SOL-YYYY-NNN ↔ EVT-YYYY-NNN) ; événement U2 clôturé ≠ dossier U3 clôturé.
2. **4.2 Collecte** — Ouverture : cible financière (comité), périmètre (défaut = tous membres adultes vivants, ajustable), échéance (liée à l'événement), mode répartition (« montant libre » ou « barème défini »). Canaux (via U4) : Mobile Money MTN MoMo/Orange Money (défaut CEMAC), virement bancaire (diaspora/gros montants), espèces (saisie manuelle trésorier/référent), carte bancaire (diaspora hors couverture). Contribution rattachée auto au compte membre U1. Suivi temps réel : cible, collecté %, contributeurs %, moyenne + médiane, liste contributeurs (anonymisée sauf accord explicite), liste non-contributeurs avec relance. Relances : J+3 (décès urgent) ou J+7 (autres) 1er rappel poli ; J+7/J+14 2e relance explicite ; ensuite relance personnelle référent ; respect fuseaux horaires/canaux ; exonérés exclus. Clôture collecte : cible atteinte + événement passé / échéance dépassée + décision comité / demande bénéficiaire. Bilan auto aux contributeurs + conseil. Excédents : report caisse familiale, transfert autre dossier, restitution (rare).
3. **4.3 Suivi des situations** — Maladie grave : journal d'évolution, planning de visites, jalons financiers (collectes complémentaires), clôture (guérison/stabilisation/décès→nouveau dossier). Deuil : suivi 1 an — visites condoléances, messe anniversaire (rappel auto à 1 an), levée de deuil (date configurable : 6 mois/1 an/2 ans), suivi orphelins (aide scolaire + visites). Difficultés financières : confidentiel (comité médiation), plan d'accompagnement, jalons tous les 3–6 mois, clôture ou transition vers aide récurrente. Rétablissement : suivi court 1–3 mois, message positif.
4. **4.4 Aide sociale & prêts** — 6 types récurrents : Bourse scolaire (annuelle), Soutien aux veuves (mensuelle/trimestrielle), Aide médicale chronique (mensuelle), Aide aux handicapés (mensuelle), Aide d'urgence (ponctuelle), Aide à l'insertion (trimestrielle). Éligibilité (conseil, configurable) : statut (orphelin, veuve, handicapé, précarité avérée), niveau de besoin (comité médiation, dossier confidentiel), ressources, rattachement familial. Bénéficiaires NON désignés publiquement. Versements via U4 (ordres de virement auto + notif trésorier) ; solde caisse solidarité insuffisant → alerte conseil (transfert caisse principale ou report). Révision annuelle (bourses) / semestrielle (continus) ; clôture avec préavis 3 mois + plan de transition. **Prêts familiaux** : dossier (emprunteur, montant, taux — zéro possible, échéancier), suivi remboursements (échéances, retards, rappels), validation conseil + bilan annuel ; impayés → comité médiation (étalement, remise partielle, conversion en don).
5. **4.5 Répartition & équité** — 3 modes : montant libre (défaut ponctuel), barème fixe (par adulte), **barème gradué** (grandes collectes). Facteurs gradués (défauts) : Branche = égale (ajustable conseil) ; Génération = active ×1,0, jeunes actifs ×0,7, retraités ×0,5 ; **Diaspora ×1,5** ; Revenu déclaré = faible ×0,5 / moyen ×1,0 / élevé ×1,5 (déclaration volontaire) ; Statut = direct ×1,0 / allié ×0,7. **Exonérations** (motifs) : maladie grave, perte d'emploi récente, précarité avérée, handicap lourd, étudiant sans revenu — confidentielles (comité médiation), membre masqué des relances. Vue agrégée d'équité (réservée conseil+comité) : contribution moyenne par branche (absolue/relative), taux de participation, évolution, retards systématiques. Cas limite branche déficitaire : médiation chef de branche, ajustement barème, plan de rattrapage, exonérations temporaires (jamais de stigmatisation).
6. **4.6 Transparence & audit** — Journal immutable (contributions+dépenses), corrections uniquement par écriture compensatoire. Accès : conseil/comité médiation/trésorier (complet), chefs de branche (leur branche), membres (leurs contributions + agrégats). Justificatif obligatoire > **10 000 FCFA** (seuil configurable) : facture, reçu, photo, contrat ; sans justificatif → signalée, régularisation ou remboursement. **Double validation dépense** : référent propose (montant, bénéficiaire, motif, justificatif) → trésorier ou membre conseil valide → virement via U4 ; désaccord → arbitrage comité médiation. Rapport mensuel auto à tous : bilan, dossiers ouverts/clôturés, contributions par branche (agrégat non nominatif), aides versées, alertes. Mode audit (conseil ou changement de trésorier) : export complet (transactions, justificatifs, bilans, journaux d'accès) pour comptable/CAC externe.
7. **4.7 Médiation & confidentialité** — Comité médiation : 3–5 membres désignés par le conseil (sagesse, impartialité, discrétion) ; intervient sur : contestation de dépense, demande d'aide confidentielle, conflit entre membres, exonération. Dossiers sensibles (maladie mentale, addiction, judiciaire, conflit grave) : visibles UNIQUEMENT bénéficiaire, référent, comité médiation, patriarche (sur demande justifiée) — invisibles aux autres membres. Journal des consultations sensibles (qui/quoi/quand), consultable par le membre concerné. Procédure de contestation : dépôt formulaire (motif+pièces) → examen ≤ **14 jours** → audition parties → décision motivée → recours patriarche/conseil. Confidentialité médicale : déclaration sans nature (« maladie grave » sans diagnostic) ; détails limités comité+référent (accord explicite) ; **purge des infos médicales après décès — délai configurable, défaut 2 ans**.

**Modèle de données U3 — 7 entités** :

- **AideSociale** : Bénéficiaire (Membre U1), type, montant, fréquence, dates, statut → versements périodiques U4.

Relations : Dossier 1→1 Collecte, 0..1 SituationSuivie, N Justificatifs ; Collecte N Contributions + dépenses (transactions négatives) ; Audit généré à chaque action sensible. Intégrité : clôture sans bilan complet interdite ; dépense sans double validation interdite ; membre ne peut être bénéficiaire ET validateur de la même dépense ; aide sociale sans validation conseil interdite ; **toute suppression interdite** (clôture+archivage).

**14 règles de gestion (R1–R14)** : R1 dossier validé par chef de branche avant ouverture collecte ; R2 collecte décès ouverte dans les **4 h** suivant l'annonce ; R3 justificatif > 10 000 FCFA ; R4 double validation ; R5 clôture impossible sans bilan transmis aux contributeurs ; R6 dossiers sensibles confidentiels (comité médiation + référent) ; R7 exonérations confidentielles (comité médiation) ; R8 journal immutable (écriture compensatoire) ; R9 rapport mensuel auto à tous ; R10 contestations traitées ≤ 14 j ; R11 aides révisées annuellement/semestriellement ; R12 prêts = validation conseil + échéancier formel ; R13 consultation dossier sensible journalisée et visible par le membre ; R14 mode audit activable sur décision du conseil.

**Cas limites** : décès dans la précarité (dossier complexe : funérailles + apurement dettes validé conseil + aide orphelins récurrente) ; maladie longue (cancer/dialyse/VIH → collectes complémentaires périodiques, transition aide récurrente) ; conflit bénéficiaire/comité (médiation, patriarche tranche en blocage) ; saturation de la solidarité (détection : baisse participation/montants moyens → prioriser, étaler, mobiliser caisse familiale) ; fraude (garde-fous : validation chef de branche, justificatifs type certificat, audit aléatoire d'un % de dossiers, signalement anonyme ; fraude avérée → clôture, restitution, sanction conseil) ; demande refusée (motif notifié, contestable) ; diaspora (collecte multi-devises €/$, conversion auto FCFA, relais diaspora par pays) ; décès d'un membre diaspora (rapatriement, workflow dédié référent local + référent diaspora, collecte plus importante).

Suivants : validation spec, maquettes des 5 écrans, interfaces U4/U2, MVP décès+sinistre, onboarding pilote à 8 mois.

### UNIVERS 4 — LES FINANCES (mémo détaillé)

**Positionnement** : « poumon technique » de l'app ; infrastructure financière de tout (U3 collectes, U2 événements, U5 votes/financements). Remplace cahiers du trésorier/transferts WhatsApp non tracés par une infrastructure **transparente, traçable, auditable**. Prérequis : U1, U2, U3. 4 rôles : infrastructure de paiement (MTN MoMo, Orange Money, virements diaspora, espèces, devises étrangères) ; garant de transparence (journal immutable, rapprochement, validations, rapports) ; planification budgétaire (budget annuel voté, suivi mensuel, alertes) ; mémoire comptable (exercices clôturés/archivés/consultables). 3 piliers : opérationnel, comptable, gouvernance. 6 questions opérationnelles (solde par caisse ?, cotisations à jour/historique 12 mois ?, comment payer/canal ?, dépenses+justificatifs ?, budget/exécution ?, à qui m'adresser/audit ?).
